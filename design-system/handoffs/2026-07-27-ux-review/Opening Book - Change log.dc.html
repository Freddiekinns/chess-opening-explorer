01 · Discover

Discover

Eight findings from the heuristic audit, all resolved. Proposed desktop · mobile · current.

01
Persistent search in the top bar

A compact search field sits in the top bar on every page, mirroring the pattern detail pages already ship. Desktop and mobile.

Search only existed in the hero. Scroll into the grid and the product's core action was gone — you had to scroll back up to look anything up.

02
One primary action in the hero

Search is the only prominent element. "Surprise me" and "Search by pasting PGN" drop beneath it as quiet links, Surprise first. Focusing the field opens a hub of recents and repertoire.

Three unequal actions competed at the same level. A beginner couldn't tell which was primary, and "PGN" means nothing to most players.

03
First run leads with content

The empty repertoire box becomes a one-line prompt, so popular openings sit above the fold from the first visit.

On every first visit a dashed empty box occupied prime space and pushed the actual content below the fold — the page led with something the user hadn't done yet.

04
One faceted filter bar

Level · Style · Family · Sort, each a button showing its current value, with a result count and Clear. Inline on desktop, a sheet per facet on mobile. Family replaces raw ECO categories.

Two unlabelled pill rows read as one row of ten. Nothing said they were independent filters, and the ECO category names were jargon.

05
Result bars label themselves

Each card reads White 31% · Draw 39% · Black 30%, tinted to its segment colour.

"W / D / B" plus three unfamiliar colours assumed the reader already knew the convention. Naming the segments removes the need for a legend entirely.

06
Search and Saved in the mobile tab bar

Four tabs: Discover · Search · Saved · Analyse.

The bar offered only Discover and Analyse, so the primary task and the repertoire were both several taps deep once the hero scrolled away.

07
One mobile filter pattern

A single Filters control with an active count, opening a sheet. Facet chips scroll horizontally showing their values.

Two adjacent filters used two different interaction models — a scrolling pill row and a dropdown — and pill labels truncated to "Intermed…".

08
Save from any card

A star in every card header — quiet at rest, orange when saved. Live in the mock: it updates both breakpoints at once.

The page promoted building a repertoire but gave no way to do it. Saving required opening a detail page first, so the loop the page pushed wasn't reachable from the page.

09
Five search and filter states drawn

Focused search (desktop), search hub, results, no results, filters sheet (mobile). All in Proposed · Discover states.

None of these existed as designs. Search behaviour was the biggest unspecified area of the page, and the build needs the empty and results cases as much as the happy path.

10
Repertoire populated, and the Saved tab behind it

The slim prompt becomes a horizontal card scroller with mini boards once anything is saved — the design system's repertoire card, count in the header, "View all" to the right. A toast with Undo confirms the save on mobile, and the Saved tab gains a real screen in both populated and empty form. Four states in Proposed · Repertoire.

The prompt and the star both promised a repertoire, and the tab bar pointed at a screen that had never been drawn — three entry points into one undesigned destination. Undo matters because the star is now a single tap on a scrolling list, where mis-taps are likely.

02 · Opening detail

Opening detail

The page kept its shape; the fixes are about what the level filter governs. Proposed desktop · mobile · current.

11
Win rates and the opening book merge into "Opening explorer"

One card, with the level filter in a raised header band. Everything the filter governs is inside that border; nothing outside it moves.

The filter sat in one card but silently drove a second, so its reach was invisible. A page-level bar was rejected: it would promise that overview, plans and resources respond too, and they don't.

12
Master games sits outside that border, labelled by source

Stays compact in the right rail with a "2,400+ Elo" source line. On mobile it moves last, below the learning resources, as a collapsed row.

It is the one list the level filter does not apply to. A full-width table was tried and dropped: it out-ranked the learning resources and spent a screen of height on browse content.

13
Reveals name their payload

"Show 4 more moves", "All 47 master games", "Show 3 more videos" — same number of controls, each stating what it holds.

Five identical grey "Show more" buttons on one page told you nothing about the cost or reward of pressing any of them. Consolidating them was rejected — expanding everything would be unusable, especially on mobile.

14
The active level echoes in sub-labels

"Games · intermediate", "Most popular at 1400–1800". Mobile especially.

On a tall mobile card the filter header scrolls out of view, leaving numbers on screen with no indication of scope.

15
ECO code set in mono

B90 uses the system's ECO pill treatment — mono, on the overlay surface — beside the character tags.

A technical identifier and flavour words ("aggressive", "sharp") were styled identically, reading as one undifferentiated row. Colour-coding complexity was considered and rejected: it's the only element that would need a legend.

16
Board pinned while the rail scrolls

Confirmed as intended behaviour and demonstrated live in the proposed desktop screen — scroll it. The board releases when the rail ends and the full-width sections begin.

Already the design-system rule for this two-column layout, but never shown in a mock — which made the taller rail look like a balance problem when it isn't one.

03 · Analyse

Analyse — blank state

Proposed desktop · mobile · current.

17
Gear and game-count selector removed

The count is defaulted, not configurable. A one-line note carries the scope. The setting can resurface in the dashboard if it's ever needed.

Almost nobody approaches the cap, so it was a control earning its space from a fraction of a percent of users while adding a decision for everyone else.

18
One header, not two

The duplicate "Ready to analyse?" prompt is gone; the hero carries a payoff-led subtitle. New string: "See which openings you actually play, and how they score — from your recent rated games."

Two headings competed on a screen with one job, and neither said what the player would get out of it.

19
Sample player and a privacy line

One tap runs a real analysis for Magnus or Hikaru. One quiet line: "Nothing is stored." Both optional — drop either.

The screen asked for a username before showing any value in return. The sample runs the same code path as any analysis, so there's no demo data to maintain.

20
Brought in line with Discover

Persistent header search on desktop; mobile tab bar matches Discover · Search · Saved · Analyse.

Chrome has to be identical across pages or the fixes to Discover create a new inconsistency instead of removing one.

21
Analysing and error states drawn

Analysing: button becomes Cancel with a spinner, inputs dim, a progress bar shows the step and games count. Error: quiet inline message under the input, username kept, button back to Analyse.

Neither state was specified. Both keep the hero and form in place so there's no layout jump, and the error uses a neutral surface rather than an alarming red block.

04 · Analyse dashboard

Analyse — dashboard

Two changes, desktop only. Proposed desktop · mobile (unchanged) · current.

22
Honest scope on the first card

"Career Totals / Overall performance" becomes "Your record" under a "This analysis" eyebrow. Wins tinted sage, losses brick, draws neutral.

The old label claimed a lifetime record for numbers that only describe the games in this run — the single clearest factual error on the screen.

23
"Games", not "GP"

The desktop column header spells it out, matching the label mobile already uses. Column widened so header and numbers stay right-aligned.

An abbreviation borrowed from sports statistics, used nowhere else in the product, and already written in full on the mobile screen.

05 · Systemic

Consistency pass

Applied across all 22 screens after a full review. Detail per finding in Design review.

24
One button spec

Primary is filled #e85d04 with #100f0e text at 8px radius, everywhere. Practice this opening became primary; Load more became tertiary — neutral surface, neutral text, no orange. Pill radii on the Analyse CTAs are gone; pill shape is now only used for the platform toggle, as the system intends.

The same action was drawn five ways across the set, and the effect was inverted priority: the most valuable action in the product (Practice) looked weaker than pagination.

25
Chrome is now identical on every page

Desktop top bar: 60px, centred nav, 240px search, nothing else — the "Surprise me!" button came out of the detail page's bar and lives in the search hub. Mobile app bar: 56px everywhere (detail was 52px). Tab bar: 64px.

Chrome that shifts between pages is the same defect the review set out to remove, and a 4px app-bar jump is visible on navigation.

26
One name: repertoire

"Your repertoire" for headings, "Repertoire" for the tab and app bar, "Added to your repertoire" for the toast. "My repertoire" and "Saved" are gone.

Four names for one feature, twice on a single screen. Second person throughout matches the system's voice note for personal features.

27
Counts add up, and mobile can page

Desktop reads "24 openings" with 6 shown and "Load more (18 remaining)". The filtered component detail reads 3, matching its 3 cards and the sheet's "Show 3 openings". Mobile Discover gained the same Load more it was missing.

The rule is now unambiguous: the count is the filtered total, the button is the difference. A spec that contradicts itself gets resolved by whoever is nearest the keyboard.

28
Copy and token corrections

"Analyse your games" in sentence case on all six Analyse screens. "Search by pasting PGN" became "Paste a game". The dashboard's mobile CTA uses the inverse token instead of #fff. The orange gradient rule under "Popular openings" is removed — it was the last use of orange as decoration.

All four were rules the system already states; three were inherited from the current build rather than introduced by the redesign.

29
Links with no destination removed

"View repertoire" (pointed at an empty page), "View all" on the desktop repertoire row (no desktop page exists) and "Edit" on the Saved tab (undefined behaviour) are all out.

Each implied a screen that was never designed. Both decisions have since been settled: desktop has no repertoire page — the row is the repertoire — and there is no manual reordering, only a fixed most-recently-saved sort.

Considered and rejected

Page-level filter bar on opening detail

Promises the whole page responds to the level filter. Only two components do.

Master games as a full-width table

Out-ranks the learning resources and costs a screen of height for browse content.

Colour-coded complexity pills

The only element on the page that would need a legend. A calm grey row reads better.

Board-driven common plans

Tapping a plan to set the board isn't supported by the current data.

Consolidating the five "Show more" controls

Decoupled reveals are correct; expanding everything at once would be unusable on mobile.

A "Start here" onboarding trio on Discover

Duplicated the filters. The faceted bar is the guided entry point instead.

Splitting the dashboard's two tables

They read fine side by side on desktop. Left as-is by decision.

Low-confidence treatment for small samples

Sample size stays implicit in the Games count.

For the build

Accessibility

Real labels on the username input, not placeholder-only. Platform toggle as a radio group. Star buttons need an accessible name and pressed state. Orange focus outline on every control, offset 2px — never the browser default.

Behaviour

Enter submits the analyse form; platform defaults to Chess.com and persists from last visit; Analyse stays disabled until a username is entered. Filter state should survive back-navigation from a detail page. The level filter on opening detail governs the explorer card only — never the master games list.

Repertoire

There is no separate repertoire page on desktop — the row on Discover is the repertoire, which is why "View all" was removed. Mobile keeps its Repertoire tab. Sort is fixed at most recently saved first; no manual reordering. Revisit both if saved counts grow past what one row can hold.

New strings

The Analyse hero subtitle, "Nothing is stored.", "Your record" / "This analysis", "Opening explorer", the labelled reveal buttons, and the facet labels Level · Style · Family · Sort are copy to ship, not just layout.

Not covered by this review

Tablet breakpoints, the practice-mode flow, sign-in, the desktop search-results state, and save confirmation on the detail-page star. Every proposed screen shows the maximal case.

The sparse opening — no videos, no studies, few master games — is deliberately not drawn. The layout degrades gracefully: each block is independent, so an empty one is omitted rather than shown empty, and the remaining blocks close up. Do not add empty-state cards for missing sections.
