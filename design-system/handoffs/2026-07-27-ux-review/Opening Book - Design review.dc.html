Opening Book

Design review — proposed set

A pass over all 22 screens in Proposed, checked against Current and against the design system. Findings are ordered by what they cost to fix late.

All 14 applied Every finding below has been actioned in Proposed. Kept here as the record of what changed and why — see change log row 24.

Headline: the structural work holds up — every audit finding is resolved and the new states close real gaps. What hasn't kept pace is the systemic layer. Buttons, chrome and naming drifted while the screens were designed one at a time, and three screens contradict themselves on numbers. None of it is hard to fix, but all of it gets expensive once it's in code.

What the redesign gets right

The filter bar is a genuine upgrade

Ten unlabelled pills became four value-showing buttons. You can read the active state without touching anything, and it survives the jump to mobile as one pattern instead of two.

Self-labelling result bars

"White 31% · Draw 39% · Black 30%" removes the need for a legend entirely. Cheapest high-value change in the set.

The explorer border does real work

Merging win rates and the book so the filter's reach is a visible edge solves the ambiguity structurally, with no explanatory copy. It's the strongest single idea in the review.

First run leads with content

Comparing current to proposed, a dashed empty box is replaced by a one-line prompt and roughly a screen of dead space disappears.

Honest labels on the dashboard

"Career Totals" → "Your record" under "This analysis" fixes a factual claim, not a style preference. Worth more than it looks.

Eleven states that didn't exist

Loading, error, no-results, empty and just-saved. The current build specifies only happy paths, so this is the part that most reduces build guesswork.

Findings

14 items. Every value quoted is the one in the file.

1 One primary action, four different buttons Cross-cutting

The same job — "the main thing to press on this screen" — is drawn four ways across the set:

radius 9999px, filled — Analyse (all six Analyse screens)
radius 8px, filled — Show 6 openings (filters sheet), Browse openings (empty Saved)
radius 12px, filled — the dashboard's mobile CTA
radius 8px, transparent + orange border — Practice this opening (detail, both breakpoints)
radius 999px, #363330 + orange border — Load more (Discover desktop)

Two consequences. The design system nominates --radius-md 8px as the button default and reserves --radius-full for pill toggles, so the pill CTAs are off-system. And "Practice this opening" — arguably the most valuable action in the product — is the weakest-looking button in the set, while "Load more" on Discover looks stronger than it.

Recommend: one spec, applied everywhere. Primary = filled #e85d04 / text #100f0e / radius 8px. Secondary = transparent with a neutral border. Tertiary ("Load more") = neutral surface, neutral text, no orange at all. Practice becomes primary; Load more stops competing.

2 Discover desktop contradicts itself on counts discover-desktop

The filter bar reads "Showing 24 openings", the grid renders 6 cards, and the button reads "Load more (14 remaining)". 6 + 14 = 20, not 24. The same screen also mixes "Showing 24 openings" with mobile's plainer "24 openings".

On the filter-bar component detail the count says "6 openings" with two filters active, but only 3 cards are drawn — so a developer can't tell whether the number counts the filtered set or the page.

Recommend: make the mock arithmetic true — 24 total, 6 shown, "Load more (18 remaining)" — and state the rule once: the count is always the filtered total, the button always the difference. Drop "Showing" so both breakpoints read the same.

3 The desktop top bar isn't the same component on every page All desktop

All four desktop screens agree on 60px and a centred nav, but the right-hand slot doesn't: Discover, Analyse and the dashboard show search only, while opening detail shows search plus a filled orange "Surprise me!". The search field is 240px on Discover and 220px on detail.

This is the same class of inconsistency the review set out to remove, and it's self-inflicted: Surprise me was demoted to a hero link on Discover but left in the bar on detail. The exclamation mark also only appears in one of the two ("Surprise me!" vs "Surprise me").

Recommend: pick one. My preference is search-only in the bar on every page, with Surprise me living in the search hub — it's a browse-y action, not navigation, and one filled orange button per screen is easier to hold to. Fix the width to 240px and drop the exclamation.

4 Four names for one feature Cross-cutting

The saved-openings feature is called "My repertoire" (Discover section, Saved page title), "Your repertoire" (search hub), "Saved" (tab bar, app bar) and "Saved to your repertoire" (toast) — sometimes twice on the same screen, since the Saved tab's bar says "Saved" above a heading that says "My repertoire".

Recommend: "Repertoire" is the domain word and the one the product already uses — make it the noun everywhere, including the tab. Second person consistently ("Your repertoire"), since the design system's voice note says second person for personal features. The toast then reads "Added to your repertoire".

5 White text on orange, once dashboard-mobile

The dashboard's mobile CTA uses color:#fff on orange. Every other orange button in the set uses the system's inverse token #100f0e. Near-black on #e85d04 is both on-system and the higher-contrast pairing.

Recommend: one-token fix. Inherited from the current build rather than introduced here, but it should not survive the handoff.

6 Mobile app bar is 52px on one screen, 56px on eight detail-mobile

Opening detail's mobile app bar is 52px; Discover, Saved (both), just-saved, Analyse, analysing, error and the dashboard are all 56px. The tab bar is a consistent 64px everywhere, so this is the only chrome measurement that drifts — and it will read as a 4px jump when navigating between pages.

Recommend: 56px, and note it in the handoff as a fixed value beside the existing 60px desktop and 64px tab-bar tokens.

7 "Search by pasting PGN" never got the agreed rewrite Discover ×3

Audit finding 2 called for plain language — "Paste a game" — because PGN is an acronym most players won't know. The demotion to a quiet link happened; the wording didn't. It still reads "Search by pasting PGN" on desktop, mobile and in the search hub.

Recommend: "Paste a game" as the label, with PGN as the technical detail inside the panel it opens. It also shortens a link that currently competes with "Surprise me" for width.

8 "Analyse Your Games" is Title Case against the system's own rule Analyse ×6

The design system specifies sentence case for headings, reserving Title Case for proper nouns and ECO codes. Every other heading in the set complies — "Popular openings", "My repertoire", "Common plans", "Your record", "Nothing saved yet". The Analyse hero is the lone exception, on all six of its screens.

Recommend: "Analyse your games". Inherited, easy to miss, and it's the largest text on the screen — so it's the most visible violation in the product.

9 The orange heading underline survives on mobile only discover-mobile

"Popular openings" on mobile keeps the 50px orange gradient rule beneath it. The desktop version dropped it, and no other section heading anywhere in the set has one — so a decorative device that used to be systematic now appears exactly once.

Recommend: drop it. It's the only remaining use of orange as decoration rather than action, which is precisely what the system's "bookmark ribbon, not wallpaper" rule prohibits. Removing it also aligns the two breakpoints.

10 Mobile Discover has no way to see more than three openings discover-mobile

The header claims 24 openings; three cards are drawn and the list simply stops at the tab bar. Desktop has "Load more"; mobile has no equivalent, so the mock doesn't say whether the pattern is pagination, infinite scroll, or just more cards below the fold.

Recommend: mirror desktop with the same tertiary "Load more" button. It's the single most-used surface in the product and currently the least specified below the fold.

11 "View repertoire" links to an empty page discover-desktop

Now that the prompt reads "Star openings to build your repertoire", the link beside it points at a page with nothing on it. Mobile's prompt has no link, so the two also differ.

Recommend: drop the link in the empty state; it returns as "View all" once the row is populated, which the repertoire state already shows.

12 "Edit" on the Saved tab has no defined behaviour saved-tab-mobile

The populated Saved tab offers Sort and Edit. Sort is specified; Edit isn't — and since every row already carries a filled star that presumably unsaves on tap, Edit may have nothing to do.

Recommend: drop Edit unless it enables reordering. If manual ordering matters for a repertoire, that's worth designing properly rather than implying with a word.

13 No desktop equivalent of the Saved page Gap

Mobile gains a full Saved screen in two states. On desktop the repertoire exists only as a row on Discover plus a "View all" link with no destination drawn — and the desktop nav has no Saved entry at all.

Recommend: decide whether desktop needs the page. If "View all" is real, it's a third nav item and a screen; if not, the link should say something honest like "Manage" or come out.

14 Housekeeping before handoff Files

The consolidated files still carry the review's own data — the eight audit findings, the annotation pins and the old "what changed" strings — in their logic. Nothing renders it, but it's confusing to read. The desktop repertoire scroller also fits all six cards exactly, so it never scrolls; and design_handoff_discover_search/ is a second, older copy of the Discover work.

Recommend: strip the dead data, add a seventh repertoire card so the overflow reads, and delete the old handoff folder so the build has one source of truth.

Still undesigned

Not defects — scope. Worth naming so nobody assumes the set is exhaustive.

Opening detail, sparse

Every detail screen shows the maximal case. Most of 12,000 openings will have no videos, no studies and few master games — and the page is mostly shelves.

Tablet

Only 1360px and 390px exist. The 7fr/5fr detail layout and the 3-up grid both need a decision in between.

Practice mode

The button exists on both detail breakpoints; what it opens has never been drawn.

Search results, desktop

Mobile has results and no-results states. Desktop has the focused hub only — the typed-and-submitted case is missing.

If you only do three things

01

Write the button spec and apply it to all 22 screens. It's the difference between a set of screens and a product, and it makes Practice this opening look as important as it is.

02

Settle the top bar and the mobile app bar so chrome is identical on every page. Cheap now, tedious later.

03

Fix the numbers and pick one name for the repertoire. A spec that contradicts itself gets resolved by whoever is nearest the keyboard.
