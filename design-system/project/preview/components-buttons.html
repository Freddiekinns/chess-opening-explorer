Four tiers, one job each. Primary is the single most valuable action on a screen, and there should be exactly one. Accent-outline is an action worth drawing in the brand colour without claiming to be what the screen is for. Secondary is grey and unremarkable. Tertiary carries pagination and other low-stakes controls — no orange at all, so it can never out-rank the action beside it.

Accent-outline was added 2026-07-30, when Practice moved into it. Practice shipped as filled primary because the spec reasoned from implementation completeness — the feature is fully built, so it can carry primary weight. That answers the wrong question: whether a feature is finished and whether it deserves the loudest control on the page are different things, and only the second decides button weight. Practice is a good action that is not yet what the opening detail page is for. See §3.4 of the UX-review spec before promoting it back, and the guard at styles/__tests__/buttonSpec.test.ts.

Before this the bundle documented two tiers while buttonSpec.test.ts described "transparent with an orange outline" as the secondary treatment — which was never true of .btn--secondary, which is grey. Naming the third tier resolves that: an orange outline is its own rank, not a weaker way of drawing grey.

Fill-to-text ratio is part of the spec, not a detail. Practice's desktop label was 11px inside 24px of horizontal padding, which reads as a colour swatch with a word in it rather than a button — and desktop said 11px while mobile said 13px for the same control. Both are 13px now with the padding brought in to match. Mobile carries a 44px minimum because it is a thumb target; desktop sizes to its text because it is a cursor target.
