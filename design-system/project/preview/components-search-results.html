What replaces components-search-hub once two characters are typed — on all three surfaces. One ranked list that scrolls, no reveal button. Fuzzy matching already absorbs typos, so there is no "did you mean", no correction notice and no explanation of what was understood: the right openings appearing is the feedback. Natural-language queries ("aggressive openings") land in this same list — the server's style intent changes the ranking, not the layout.

No count line, and no number anywhere. An earlier draft put "14 openings match" above the list. It was cut once the number turned out to be unusable: the search counts every record scoring above zero, which for "sicilian" is 4,269 against a family of roughly 1,710. Anyone reads that as a claim about how many Sicilians exist. Counting only the rendered rows instead would have been true but useless — it always says twenty. A count that cannot be trusted and a count that never varies are both worse than the silence the page already had, and the design's own argument covers it: the openings appearing are the feedback.

Surprise me sits outside the scroller. It used to vanish on the second keystroke — the way out of a search that is not working disappearing exactly when the user is flailing. Twenty results deep is where someone gives up, so that is where it has to still be on screen. It is reachable by arrowing one past the last result, not only by clicking.

The icon and the label stay on every surface. Only the hint varies: the top-bar dropdown is a fixed 238px and the label plus hint need ~265px, so there the hint would wrap "Surprise me" onto two lines. It moves to title and to an aria-label of "Surprise me — jump to a random opening" rather than being dropped — the row still explains itself on hover and to a screen reader, and the accessible name begins with the visible text, which WCAG 2.5.3 requires. A shorter visible hint was the obvious alternative and was rejected: "Surprise me · Random" reads as two words for one idea, and renaming the row to fit would fragment a label that is identical on four surfaces.

"Saved", not a star. Repertoire membership rides on the result row rather than sitting in a section of its own — a saved opening that also matched the query would otherwise be drawn twice, at two different ranks. It is a text badge because everywhere else in the app a star is a control you press to add or remove; on a row whose whole job is to navigate, the same star would invite a tap that does something else entirely.
