Surprise me · one variant, everywhere

One row for every search surface and both states. The hero dropdown, the top-bar dropdown and the mobile overlay all draw this, before and after you type. It used to be two rows: the pre-typing hub was built on the --text-* scale (13px medium name, ECO as inline mono text in a meta line) and the results list on the --font-size-* legacy aliases (16px semibold name, ECO as a pill, moves on their own line). Typing a second character therefore changed an opening's size, weight, layout and hover behaviour — the same opening, redrawn as a different kind of object. Merged 2026-07-30; the guard is components/shared/__tests__/search-row-parity.test.tsx.

No leading icon on any row. Hub rows led with a clock or a star and result rows led with nothing, which put the opening's name 26px further right before you typed than after (13px vs 39px, measured). The name's left edge moving is the most visible drift there is, and it was being caused by the very marker meant to reassure you nothing had changed. The clock and the star also only repeated the section heading immediately above them — "Recent", "Your repertoire" — once per row. The heading says it once, which is enough. The mobile chevron went the same way: it appeared on mobile results and not on mobile hub rows, so it was drift wearing an affordance's clothes. Nothing leads a row now, on any surface, in either state.

Bounded by border and radius, not by a fill. The hub's rows were filled rgba(0,0,0,.2), which reads well at four rows and stacks into a ladder at twenty. Hover brings the fill in, so a row still reads as a discrete component without all of them shouting at once. The keyboard cursor is styled identically to hover — arrowing and pointing are the same act of "this one". No transform: the old results list lifted a hovered row by half a pixel, which is jitter rather than an affordance.

The ECO pill does not react to hover. It is metadata. The old results list turned it brand orange when its row was hovered, which made a label look pressable.

Surprise me carries an orange label, and nothing else. It is the one row that is not an opening: every other row goes to a named position, this one takes an action. The app already marks that difference in colour — .cancelBtn, .back-link and .reset-filter-btn are orange text, opening names are white — so this follows the rule that already exists rather than inventing a marker.

Colour only. Same 14px, same 600 weight, same box, same hover, and the hint stays muted. The results list used to make it orange and semibold-against-regular and give it a filled hover with the hint flung to the right margin, which put the escape hatch above the twenty real answers it sits under. Changing its kind is right; changing its rank is not. If a future row needs the same treatment, it is .rowNameAction — an action in a list of destinations, nothing more.

The glyph question is the reason it ended up with none. Sparkles is the industry's AI mark and promises intelligence that is not there. Shuffle and dice both name chance rather than a destination, and shuffle specifically reads as a mode you switch on rather than a jump you take once. A gift or an opening box reads as a reward, and mystery-box imagery carries a loot-box association this has no business borrowing. The payoff here is a chess opening, chosen at random — a smaller and more honest promise than any of those pictures make. The second line says exactly that in words, and words were what the row needed.
